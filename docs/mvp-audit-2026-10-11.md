## Checkpoint de este incremento

- Se preservó el volumen PostgreSQL existente. Se agregaron n8n y Ollama a Compose con puertos de loopback y volúmenes propios. No se añadió SaaS ni credencial facturable.
- Las migraciones `0007` y `0008` amplían la restricción de acciones de caso; no borran datos. `cancel_unverified` exige `manual_review` por discrepancia de importe y cancela intentos nunca verificados. `request_mock_refund` exige pago con evento verificado y proveedor sin prueba tras cinco minutos, registra una reversión simulada por intento y deja la confirmación prohibida. Ambas decisiones bloquean las filas y son idempotentes.
- `workflows/n8n/wf_maintenance.json` fue importado y ejecutado una vez contra Next.js. Con autorización explícita del usuario se publicó y activó su disparador cada cinco minutos en la instancia local; `n8n list:workflow --active=true --onlyId` devolvió `travelmind-maintenance` y el reinicio cargó un workflow publicado. Aún no se observó una ejecución disparada por el cron. `pnpm workflows:run` conserva la ejecución manual sin n8n.
- Ollama Qwen2.5 1.5B y Nomic embeddings se descargaron localmente. Se indexaron 20 chunks. Una consulta HTTP real con datos ficticios confirmó el camino `ollama` + `semantic` + fuentes; otras consultas durante el ajuste ejercitaron el fallback por timeout/JSON incompleto.
- Pendiente para completar el encargo integral: cinco workflows independientes con pruebas de fallos, resolución operativa de proveedor/notificaciones, evaluación de IA, escenarios E2E negativos y revisión WCAG completa. No se declara terminado el MVP integral.

Verificación de este checkpoint: `pnpm db:migrate`, `db:seed`, `rag:index --embed`, `lint`, `typecheck`, `test` (61), `test:integration` (36) y `test:e2e` (6): **103 pruebas aprobadas en total**. `test:e2e` incluyó build exitoso. `docker compose ps` mostró PostgreSQL y Mailpit sanos, además de n8n y Ollama activos; `ollama list` confirmó ambos modelos. El flujo n8n manual arrojó HTTP 200 y `checked=0`, `completed=0` al no haber eventos pendientes. Se probó `pnpm workflows:setup` dos veces sin mostrar ni cambiar el token.
`pnpm exec tsx scripts/check-case-rollback.ts` aplicó todas las migraciones (incluidas 0007/0008) y el rollback conjunto en una base recién creada para esta comprobación; la eliminó al terminar. No se ensayó rollback con decisiones reales persistidas.
