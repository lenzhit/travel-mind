## Checkpoint de este incremento

- Se preservó el volumen PostgreSQL existente. Se agregaron n8n y Ollama a Compose con puertos de loopback y volúmenes propios. No se añadió SaaS ni credencial facturable.
- Las migraciones `0007` y `0008` amplían la restricción de acciones de caso; no borran datos. `cancel_unverified` exige `manual_review` por discrepancia de importe y cancela intentos nunca verificados. `request_mock_refund` exige pago con evento verificado y proveedor sin prueba tras cinco minutos, registra una reversión simulada por intento y deja la confirmación prohibida. Ambas decisiones bloquean las filas y son idempotentes.
- `workflows/n8n/wf_maintenance.json` fue importado y ejecutado una vez contra Next.js. Con autorización explícita del usuario se publicó y activó su disparador cada cinco minutos en la instancia local. En este primer checkpoint todavía no se había observado el cron; la verificación posterior se documenta abajo. `pnpm workflows:run` conserva la ejecución manual sin n8n.
- Ollama Qwen2.5 1.5B y Nomic embeddings se descargaron localmente. Se indexaron 20 chunks. Una consulta HTTP real con datos ficticios confirmó el camino `ollama` + `semantic` + fuentes; otras consultas durante el ajuste ejercitaron el fallback por timeout/JSON incompleto.
- Pendiente para completar el encargo integral: cinco workflows independientes con pruebas de fallos, resolución operativa de proveedor/notificaciones, evaluación de IA, escenarios E2E negativos y revisión WCAG completa. No se declara terminado el MVP integral.

Verificación de este checkpoint: `pnpm db:migrate`, `db:seed`, `rag:index --embed`, `lint`, `typecheck`, `test` (61), `test:integration` (36) y `test:e2e` (6): **103 pruebas aprobadas en total**. `test:e2e` incluyó build exitoso. `docker compose ps` mostró PostgreSQL y Mailpit sanos, además de n8n y Ollama activos; `ollama list` confirmó ambos modelos. El flujo n8n manual arrojó HTTP 200 y `checked=0`, `completed=0` al no haber eventos pendientes. Se probó `pnpm workflows:setup` dos veces sin mostrar ni cambiar el token.
`pnpm exec tsx scripts/check-case-rollback.ts` aplicó todas las migraciones (incluidas 0007/0008) y el rollback conjunto en una base recién creada para esta comprobación; la eliminó al terminar. No se ensayó rollback con decisiones reales persistidas.

## Continuación integral — 2026-10-11

- La migración no destructiva `0009_graceful_fantastic_four.sql` añade `consultation_runs`: sesión, correlation ID, modo, recuperación, número de opciones y tiempo de procesamiento. No guarda mensaje, prompt ni viajero. `wf_consultation` procesa hasta 50 metadatos por pasada; la retención los elimina tras siete días y evita borrar sesiones todavía referenciadas.
- Se importaron y publicaron `wf_consultation`, `wf_quotation`, `wf_reservation`, `wf_notifications` y `wf_exception_handling`, todos con intervalos de cinco minutos, identidad `system` y HTTP a Next.js. Las cinco ejecuciones manuales desde CLI terminaron con HTTP 200; los cinco obtuvieron después al menos una ejecución `mode=trigger`, `status=success` en la base de n8n. La cotización vence hasta 100 emitidas por pasada; reserva concilia reversos mock/aprobaciones; notificaciones drena outbox; excepciones cuenta alertas sin PII y ejecuta retención. Ninguno cobra, aprueba HITL ni confirma proveedor por sí solo.
- El workflow anterior de mantenimiento creó cuatro registros `running` sin completar el nodo HTTP. Se reimportó con nombres de nodo y configuración de guardado equivalentes a los flujos nuevos, se publicó de nuevo y el disparo horario ID 19 terminó `success` a las 10:26:10 de Lima (15:26:10 UTC). Los cuatro registros antiguos siguen en la base local como evidencia diagnóstica; no se borraron. El endpoint registró ejecución n8n 13 y HTTP 200 antes de la corrección, pero ese estado no se tomó como éxito.
- El recorrido HTTP real `pnpm test:smoke` pasó con Ollama `qwen2.5:1.5b-instruct-q4_1`, recuperación semántica pgvector, cotización, revalidación, consentimiento, pago mock, comprobante mock y `confirmed_demo`. Su consulta posterior quedó registrada `ollama|semantic|3` y marcada como procesada por el workflow. Mailpit capturó ocho mensajes tras las entregas de prueba; una reserva ficticia mostró cuatro emails y cuatro WhatsApp mock en `sent_demo`.
- Con Mailpit detenido, un segundo `pnpm test:smoke` conservó `confirmed_demo`. `pnpm workflows:run` dejó cuatro emails en `failed` (un intento) y cuatro WhatsApp mock en `sent_demo`. Se restauró Mailpit; el siguiente disparo horario de `wf_notifications` convirtió los cuatro emails en `sent_demo` al segundo intento y Mailpit mostró cuatro capturas nuevas. No se leyó contenido ni se envió correo externo.
- `pnpm ai:evaluate` midió cuatro casos locales: 4/4 preferencias esperadas, 4/4 con Ollama y retrieval semántico, ocho resultados con precio y fuente del catálogo, p50 7459 ms, p95 10380 ms. Estos percentiles describen solo cuatro consultas secuenciales de esta CPU, no carga productiva.
- `pnpm test:load` midió solo lectura local de catálogo: 100/100 respuestas correctas, concurrencia cinco, p50 37.3 ms y p95 58.82 ms en esta máquina. No mide IA, pago, reserva ni capacidad productiva.
- `pnpm test` pasó 63 pruebas, `pnpm test:integration` 38 y `pnpm test:e2e` 6, **107 en total**. `test:e2e` compiló el build de producción y validó navegador contra PostgreSQL de test y Mailpit local. `pnpm typecheck`, lint de `src`, `tests` y `scripts`, y `pnpm api:docs` pasaron. La comprobación de lint completo se hará tras retirar el script diagnóstico temporal.
- Sigue pendiente la orquestación por eventos de consulta/cotización/reserva, más casos E2E negativos y WCAG 2.2 AA completa. No se declara terminado el MVP integral.
